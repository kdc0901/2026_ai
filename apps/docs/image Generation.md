## 이미지 생성 화면 기능명세서

---

### 프론트엔드 기능명세서

#### 1. 화면 레이아웃 및 디자인 명세

- **파일 위치**: `apps/web/app/generate/page.tsx`
- **디자인 가이드 참고**: `Design Guide.md` - “이미지 생성 화면(프롬프트 + 스타일 옵션 + 생성 버튼 + 로딩 애니메이션)”

1. **페이지 헤더**
  - **UI 구성**: 상단에 화면 제목 “이미지 생성”을 표시합니다.
  - **상호작용**: 없음

2. **프롬프트 입력 필드**
  - **UI 구성**: 프롬프트 입력 필드를 제공합니다. 현재 구현은 기본 `<input>`을 사용합니다.
  - **상호작용**:
    - 사용자가 텍스트를 입력합니다.
    - 메인 페이지에서 넘어온 경우 `/generate?prompt=...` 쿼리스트링의 `prompt`를 초기값으로 설정합니다.
  - **오류 처리/제약**:
    - 프롬프트가 비어있으면 생성 버튼은 비활성화됩니다.

3. **스타일 옵션 선택**
  - **UI 구성**: 드롭다운(select)으로 스타일을 선택할 수 있습니다.
  - **상호작용**:
    - 사용자 선택값은 `style` 상태로 보관됩니다.
  - **기본값**:
    - 기본 스타일은 `"기본"`입니다.
  - **추가 고려사항(차후)**:
    - 디자인 가이드에 따라 슬라이더(색감/텍스처/분위기 등) 옵션으로 확장 가능

4. **생성 버튼**
  - **UI 구성**: “생성” 버튼을 제공합니다(`@workspace/ui`의 `Button` 사용).
  - **상호작용**:
    - 클릭 시 이미지 생성 동작을 시작합니다.
  - **오류 처리/제약**:
    - 프롬프트가 비어있거나 생성 중(`isGenerating`)이면 버튼은 비활성화됩니다.

5. **로딩 상태(애니메이션/상태 표시)**
  - **UI 구성**:
    - 생성 중에는 버튼 텍스트가 “생성 중...”으로 바뀝니다.
    - 페이지 내에 로딩 상태 안내 문구(“이미지를 생성하고 있습니다...”)와 스피너를 표시합니다.
  - **상호작용**:
    - 현재 구현은 목업 딜레이(약 1.2초) 후 생성 완료 상태로 전환합니다.

6. **메인 페이지로 돌아가기**
  - **UI 구성**: “메인 페이지로 돌아가기” 링크를 제공합니다.
  - **상호작용**: 클릭 시 `/`로 이동합니다.

#### 2. 사용자 흐름 및 상호작용

1. **메인 페이지 → 이미지 생성 페이지 이동**
  - 사용자가 메인에서 프롬프트 입력 후 “이미지 생성” 버튼을 클릭합니다.
  - `/generate?prompt=...`로 이동하며, 이미지 생성 화면에서 해당 프롬프트가 기본값으로 설정됩니다.

2. **이미지 생성 실행**
  - 사용자가 프롬프트/스타일을 설정한 후 “생성” 버튼을 클릭합니다.
  - 생성 중 로딩 UI가 표시됩니다.

3. **(추후) 생성 결과 확인 및 저장/공유**
  - 생성된 이미지를 미리보기로 확인하고, 갤러리 저장/커뮤니티 공유 플로우로 연결합니다.
  - 현재 버전에서는 생성 결과 렌더링/저장/공유는 미구현입니다.

### 백엔드 기능명세서

> 현재 단계에서는 **백엔드 연동을 보류**하고, 이미지 생성 화면에서는 목업 로딩만 수행합니다. 아래는 프론트 구현 흐름에 맞춘 **추후 구현 대상 API 명세**입니다.

#### 1. 프롬프트를 통한 이미지 생성 API (추후)

- **파일 위치**: `app/api/generate-image/route.ts`
- **HTTP 메서드**: `POST`
- **요청 데이터(예시)**:
  - `{ prompt: string, style?: string }`
- **응답 데이터(예시)**:
  - `{ success: boolean, imageURL: string }`
- **프론트 연동(예정)**:
  - 요청 시작 → `isGenerating=true` + 로딩 UI 표시
  - 성공 시 `imageURL` 기반으로 결과 미리보기 표시
  - 실패 시 오류 메시지(예: “다시 시도해 주세요”) 표시

#### 2. (선택) 생성 이력/갤러리 저장 API (추후)

- **목적**: 사용자가 생성한 이미지를 개인 갤러리에 저장/조회할 수 있도록 지원
- **예상 엔드포인트(안)**:
  - `POST /api/gallery` (생성 결과 저장)
  - `GET /api/gallery` (개인 갤러리 조회)
